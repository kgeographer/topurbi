## WHG index modernization — blog post 27 May 2026

Read https://blog.whgazetteer.org/2026/05/27/whats-new-in-the-whg-index/

**What is actually new** (scale and algorithm, not concept):
- Index now draws from 6 gazetteers (OSM, GeoNames, Wikidata, Getty TGN, Pleiades, LoC),
  covering 47M places / 67M toponyms / 7M clusters. Previously 2 sources.
- **Symphonym**: phonetic embedding search (G2P + articulatory features, 0.79 cosine threshold)
  enabling cross-script and historical-spelling matching — important for Alcedo's 18c Spanish.
- 4-phase clustering: explicit cross-refs → exact toponym + spatial → phonetic similarity →
  spatial proximity + feature-type alignment.
- Infrastructure moved to Pitt Center for Research Computing (GPU-enabled).

**What is NOT new — the founding WHG data model (Karl's design):**
WHG was built from day one as an attestation system. The pipeline:
  1. Any contributor uploads a dataset (= a set of place attestations)
  2. They initiate reconciliation against Wikidata/GeoNames — returned as prospective matches
     based on name variants (potentially hundreds per authority record)
  3. Contributor pages through records accepting/rejecting matches → adds `place_link` IDs
  4. A second reconciliation step matches against the WHG ES index; records with shared
     authority IDs are auto-clustered into place graphs
  5. Unmatched records become new seeds in the index
The result: a place portal page (e.g. Istanbul) shows a dozen attributed records from many
datasets — ALL attestations, all attributed. That IS the product. This concept is the core
structure of WHG and predates the current team. The blog post's framing of "attesting evidence
rather than uploading new place records" as a new direction misrepresents this.

**Implications for Alcedo:**
- The LP-TSV upload path remains valid — Alcedo records are attestations in exactly the sense
  WHG was designed for
- 6,688 `indias:` links enable auto-clustering in phase 1 (explicit cross-references)
- Symphonym phonetic matching improves reconciliation for colonial name variants
- AAT feature types support phase 4 alignment
- Worth asking Stephen whether the LP-TSV upload path or a direct clustering-pipeline ingest
  is the practical entry point under the new infrastructure

Read Stephen's blog post and the GoW demo site. Key findings:

**What Stephen and Palak have built:** An experimental pipeline that takes scanned printed gazetteers
and produces a structured, map-browsable dataset. Pipeline: page scans → Surya OCR → Llama 3.3
(structured extraction: names, place types, coords, populations) → gpt-oss/Qwen3 validation →
WHG reconciliation. Output is a static HTML/JS app. Applied to an 1856 7-volume *Gazetteer of the
World*, yielding ~116,000 entries. Runs on Pitt computing infrastructure.
